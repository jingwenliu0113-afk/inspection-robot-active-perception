# detector-v2：困難負樣本微調的準備紀錄（decision 027）

**狀態**：資料、訓練程式、評測程式完成；**訓練需要 RTX 5070 Ti，尚未執行**。
這裡只有開發資料（train / dev）上 `detector-v1` 的基準與分析。test 從未執行過任何 detector，影像也尚未下載。
三種驗證不得混用：這裡全部是**真實照片**（影像層級），不是機器人相機，也不是實機。

## 1. 為什麼做

- R0a 的 A2 未通過：偏難負樣本 false present 9.2%，判準是 ≤ 1%。
- v3 開發資料顯示：只靠影像資訊（門檻、框形狀）壓不下來。zone 過濾只能排除 zone 外的相似物件。
- 67 張誤報中有 26 張是管件、閥門、柱狀設施（`docs/v3-development.md` §1.2）。巡檢現場就在 zone 內放著這類物件。

## 2. 資料（`data/detv2/`，`python -m activeperception.detv2.data split`）

| split | 正樣本 | 負樣本 |
|---|---|---|
| train | COCO train2017 消防栓 426 張（CC BY / BY-SA / 無已知版權） | 確認負樣本 491 張、相似物件 545 張 |

| test（凍結、未執行） | COCO val2017 NC / ND 62 張（只評分）、v3 保留組影像層級 72 張 | v3 保留組確認負樣本 737 張 |

- 影像下載：train 1,462 張、dev 613 張，0 失敗。R0a 已下載的影像以硬連結重用，不重複下載。
- 授權：訓練只用允許衍生的授權；NC / ND 影像只在 test 中評分。

## 3. 困難負樣本分析（`detector-v1`，CPU，約 640×480 像素數）

| 群組 | train：判 present（≥ 0.7） | dev：判 present | dev：absent blocked（≥ 0.02） |
|---|---|---|---|
| **人工確認的負樣本** | **36 / 491 = 7.3%** | **31 / 245 = 12.7%** | 51.0% |
| 相似物件：雕像 / 玩偶 | 1 / 213 | 0 / 106 | 14.2% |
| 相似物件：街道設施 | 1 / 160 | 1 / 84 | 19.0% |
| 相似物件：管件 | 0 / 68 | 0 / 18 | 5.6% |
| 相似物件：其他 | 1 / 104 | 0 / 65 | 15.4% |
| 正樣本 COCO（有框，found@0.7） | 338 / 426 = 79.3% | 15 / 24 = 62.5% | — |
| 正樣本 v3 開發組（影像層級） | — | 64 / 71 = 90.1% | — |

發現：

- **真正困難的是「人工確認的負樣本」**。Open Images 會把模型認為「可能有消防栓」的影像送去人工確認，所以這群影像天生就偏難。
  - dev 與 train 的誤報率都與 R0a 正式集（9.2%）同一個量級。
- **按類別挑的相似物件影像大多很容易**：19 類中只有 4 類出現 1 張誤報，合計 < 1%。
  - 在訓練中，它們提供多樣的背景物件，避免模型只學到確認負樣本這一種分布。
  - 誤報的主要訊號來自 491 張確認負樣本。
- **COCO 正樣本的召回偏低**（found@0.7：train 79.3%、dev 62.5%）：COCO 有大量小型或被遮擋的消防栓。
  - 所以 decision 027 的 T2 用「與 v1 成對比較」，不用絕對門檻。這是事先就寫定的設計。
- dev 的確認負樣本只有 245 張，誤報 31 張。T1 的 1% 目標在 dev 上的解析度有限，最終判斷以 test（737 張）為準。

## 4. 程式與檢查

- `activeperception/detv2/train.py`：
  - 與 v1 相同的架構與類別清單；batch norm 凍結，訓練最後 3 個 stage。
  - 預先登錄 3 個設定：`base`、`lowlr`、`negheavy`。
  - CPU smoke test（8 張、2 iterations）通過：權重可被評測程式載入，輸出格式與 v1 相同。
- `activeperception/detv2/evaluate.py`：
  - 真實照片的 present / found / absent blocked、成對的修好 / 弄壞計數；
  - 模擬畫面的保持度：v1 在 `v3-dev` 清楚可見的視角是 634 / 637 判 present，absent 視角 false present 0。
- 程式拒絕在 test 清單上下載、訓練或執行 detector（`tests/test_detv2.py`）。

## 5. RTX 恢復後的步驟（需要 GPU lock）

1. 在 RTX 5070 Ti 上取得共享 GPU lock，依序訓練 `base`、`lowlr`、`negheavy`。預估每個 10–20 分鐘。
2. 在 dev 上評估三個設定：真實照片，以及 `v3-dev` 的模擬畫面。依 decision 027 §4 的規則選一個；都不合格就不採用。
3. 產生 `detv2-sim`（新 namespace），下載 test 影像。v1 與 v2 各在 test 上執行一次，判定 T1–T5。
