# 往真實巡檢發展：後續建議（尚未啟動）

- **日期**：2026-10-14
- **狀態**：只是建議。沒有啟動任何新階段，也沒有採購；每一步都需要使用者決定。
- SPEC 把「真實相機 / 實體機器人驗證、sim-to-real」列為 Optional；detector 微調屬於 Advanced A。

## 現在能說什麼、不能說什麼

| 可以說（模擬中、預先登錄、只跑一次） | 不能說（沒有驗證過） |
|---|---|
| 判定規則 v2 把漏看變成 `inconclusive`，而不是 `absent` | 在真實 depth 雜訊下，這個保證仍然成立 |
| 主動選視角在 Nav2 實際導航下仍勝過 Single / Random | 在真實機器人上，同樣的優勢存在、成本可接受 |
| 用 depth 對設施地圖精修位姿後，定位誤差 p95 約 0.3 cm | 在真實里程計、地圖誤差、動態環境下的定位精度 |
| COCO 預訓練的 detector 對 Gazebo 消防栓幾乎不誤報 | 對真實影像中的目標，detector 的召回率、誤報與 confidence 校準 |

## 最大的風險（依優先順序）

1. **真實 depth 雜訊 vs 3 cm 的看穿容忍值**：`decision-v2` 的安全性建立在「物件所在位置不可能被看穿」。
   - 真實雙目 / 結構光相機在 2 m 處有公分級雜訊與缺值，可能讓視線「穿過」物件。
   - B0 已經證明位姿誤差會讓這個保證失效，depth 誤差是同一類風險。
2. **部分遮擋時的偵測**：模擬中只露出約四分之一時，confidence 已在 0.39–0.76 之間擺動（failure analysis §9）。
   真實影像的光照、模糊與相機校正會放大這個問題。
3. **定位**：模擬中的里程計接近理想、起點已知、圍牆提供特徵；即使如此，3 / 40 個場景的起點仍然無法精修（§10）。
4. **評分用的真值**：實機沒有 `/gt/odom` 與物件標籤，必須另外量測，否則無法驗證 false absent 與定位誤差。
5. **已知的方法限制**：rule-nbv-v2 分數平手時按編號選（§4）；停點重定位很慢（§11）。這兩項可以在模擬中先修，但都需要新版本與新資料。

## 建議順序

每一步都先寫 decision log（協定、判準），用新的 namespace 與資料，結果與模擬分開報告。前一步沒過就停。

| 步驟 | 內容 | 需要採購？ | go / no-go 判準（建議） |
|---|---|---|---|
| **R0a 真實影像的 detector 檢查**（Advanced A 的前半） | 用手機或 RGB-D 相機拍實際目標（或替代物）：可見、部分遮擋、不存在；標註後評估 `detector-v1` | 否（或一台相機） | 可見時的偵測率、部分遮擋時的 confidence 分布、absent 時的最高 confidence 是否低於 0.02（`decision-v2` 的凍結值） |
| **R0b depth 雜訊下的安全性**（模擬） | 在 Gazebo depth 上加入實際相機規格的雜訊與缺值模型，於新的開發資料測 v2 的 false absent 與 geometric risk | 否 | geometric risk = 0；若不為 0，先設計新的容忍值 / 餘裕（新版本） |
| **R0c 方法修正**（模擬，可選） | rule-nbv-v2 平手時的處理、Nav2 到點容忍值與位姿精修一致化 | 否 | 在新的開發資料上改善，且安全指標不退步；最後以新的正式資料驗證 |
| **R1 硬體與場地** | 機器人（例如 TurtleBot 4）＋桅桿＋校正過的 RGB-D 相機；可建圖的場地；目標物與遮擋物；外部真值（例如 AprilTag 或 motion capture） | **是** | 由使用者決定預算與場地 |
| **R2 實機 B0** | 以 decision 015 / 016 的判準在少量實機 episode 上驗證：到點率、定位誤差、位姿精修是否成立、所有停點聯集的安全性 | 是 | 與模擬 B0 相同的判準；任何一項未過就停下分析 |
| **R3 實機正式評估** | 預先登錄、新資料、只跑一次；與模擬結果分開報告 | 是 | 依當時的協定 |

R0a 與 R0b 不需要機器人就能回答最大的兩個風險，建議最先做。結果若顯示真實感知或 depth 雜訊會破壞 v2 的安全保證，就應先修正方法，再考慮採購。

## 不建議現在做的事

- **Advanced C（RL）**：使用者已決定不做；而且目前最大的不確定性在感知與定位，不在選視角策略。
- **SLAM、多機器人、完整自主巡檢產品**：超出本研究的問題範圍（SPEC「不做什麼」）。
- **重用已封存的資料**：`core` test、`holdout`、`nav-b2` 都已用過，不得用於任何新版本的開發或驗證。

## 需要使用者決定

1. 是否先做 R0a / R0b（不需採購）。
2. 實際巡檢的目標物與場地，決定 R0a 要拍什麼。
3. 是否採購硬體（R1 之後）。
