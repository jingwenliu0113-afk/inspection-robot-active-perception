- **日期**：2026-10-15
- **狀態**：開發中。本檔規定 v5 的範圍、資訊邊界、開發資料與指標；**正式測試另寫 decision**（凍結後才產生新資料，只跑一次）。
- **是否在看過正式結果後才新增**：是，動機來自 decision 032 報告的 v4 代價（absent 較難判）。
  因此 v5 是**新版本**：v4 的凍結設定與正式結果（`results/v4/`）都不修改；`v4` / `v4-dx` 已用過，不得用於 v5 的開發、調參或正式驗證。

## 1. 使用者指示與選擇

- 使用者 2026-10-15：「你看一下目前進度 然後接著做」。
- NEXT.md 列出的三個候選中，「實機量測」需要採購（使用者已決定不買）。剩下兩個：
  1. zone 內相似物件：再做一輪 detector（需要新的困難負樣本下載與 GPU 鎖；上一輪 T1 未通過，decision 030）；
  2. absent 可判率：用多個視角估計相機固定的比例偏差，縮小 v4 的餘裕。
- 先做 2：只需要 Mac 與既有開發資料，不需採購、GPU 或大型下載，且直接針對 decision 032 量到的代價。1 仍待使用者決定。

## 2. 問題（從已報告的結果與 v4 開發資料推得）

- v4 對每個視角試 5 個 depth 比例假設（0.96–1.04），把成本在最佳 1.1 倍內的假設之位姿離散度加進餘裕（decision 031）。
  這把「比例與平移互相補償」的錯誤收斂擋下來，代價是餘裕變大（成功時中位 9–10 cm，v3 為 6 cm），absent 較難判：
  正式結果 D2×L2 absent@5 0.975 → 0.863、D3×L1 0.713 → 0.637、D1×L1 Rule budget 3 −0.081（decision 032）。
- 但相機的比例偏差**是相機固定的**（D1 +1%、D2 +2%、D3 −2.5% 加每張 1% 浮動；真實 D435 也是固定偏差加小幅浮動，decision 028）。
  v4 每個視角都從 0.96–1.04 重新猜，沒有利用「前面看過的視角已經透露了這台相機的比例」。
- 開發資料上的初步觀察（`runs/v4-dev`，`v3-dev`，凍結 v4 的每視角精修）：單一視角估到的比例很分散（MAD 1.5–2.2%，80 多個視角卡在 1.045 的上緣），
  但精修成功視角的**中位數**落在真值的網格解析度內：D1 1.005（真值 1.01，網格到不了 1.01）、D2 1.015（1.02）、D3 0.975（0.975）。

## 3. 範圍：只改位姿精修的比例假設帶（`nav-pose-v5`）

- 比例假設改為以**校正值** ŝ 為中心、半寬 B 的帶（v4 是以 1.0 為中心、半寬 0.04）。
- 其餘與凍結的 v4 相同：搜尋範圍 max(15 cm, 4σ)、尺度雅可比、成本 1.1 倍內假設的離散度加進餘裕、先驗閘門 3σ、矛盾時不提供看穿、
  `decision-v4` zone 過濾（±8% depth 區間）、see-through-v3、decision-v2 門檻、`detector-v1`、rule-nbv-v2。
- **看穿判定仍用原始 depth，不用 ŝ 校正**：校正後的 depth 在 D3 的逐張浮動下會往「看起來更遠」的危險方向偏，與 3 cm 容忍值的前提不同。
  ŝ 只用來選擇位姿精修要試哪些比例。

## 4. 資訊邊界（部署時可得）

自我校正只用部署時拿得到的東西：**同一台機器人先前巡檢**的機載 depth、定位器的估計位姿與回報不確定度、設施地圖。
不用真實位姿、物件位置或任何標籤。具體做法（候選，開發中選擇）：

| 候選 | 校正值 ŝ | 說明 |
|---|---|---|
| `med` | 先前視角中，凍結 v4 精修成功者的擬合比例中位數 | 最簡單；解析度受 v4 的比例網格限制（0.005，且 0.97 / 0.99 / 1.01 / 1.03 不可達） |
| `prof` | 每個先前視角在細網格比例上的最佳成本曲線（除以自身最小值）加總後的最小點 | 真正的多視角共同估計；計算較重 |

帶的半寬 B（候選）：

| 候選 | B | 說明 |
|---|---|---|
| 固定 | 1%–3%（消融） | 依 decision 028 量到的逐張浮動（最多約 1.04%）與校正誤差設定 |
| `jit` | 2 × 靜止重拍估得的逐張浮動 + 校正誤差 | 機器人靜止時連拍兩張，兩張 depth 的逐像素比例中位數直接量到逐張比例變化，與位姿無關（模擬中以 `rng_for` 加 `rep` 鍵抽第二張雜訊） |

為什麼不在同一集內即時估計：Core harness 的前提是「某視角的觀測只取決於（episode, viewpoint）」（teleport 語意），Oracle 的 peek 與全視角風險都依賴它。
同一集內用前面視角校正後面視角，會讓觀測依賴路徑。改用**先前巡檢**（獨立的校正資料）保持每個視角的觀測不變。

## 5. 開發資料與條件

- **評估**：`v3-dev`、`v3-dev-dx`。**校正來源**：與評估資料不同的 namespace（例如以 `v3-dev-dx` 校正、`v3-dev` 評估，反之亦然；`r0b-dev`、`nav-b1` 測少量校正視角時的穩定性）。
  校正與評估使用同一個誤差條件（同一台相機、同一個定位器）。
- **不得使用**：`core` test、`holdout`、`nav-b2`、R0a 正式集、`r0b`、`v3`、`v3-dx`、`v4`、`v4-dx`、`detv2-sim`、`data/detv2/test.csv`。
- **誤差條件**：D0×P0、D1×L1、D2×L2、D3×L1、D3×P0、D1×L2 回報 L1；`v3-dev-dx` D1×L1、D3×L1。
- **校正錯誤的壓力測試**（只報告）：校正後相機比例漂移（例如以 D3 校正、實際偏差改為 −1% 或 −4%），以及校正視角很少時。

## 6. 指標（與 v4 相同，不放寬）

- 安全：FA、FP、GR、全視角 GR、佔用位置看穿（0.06 m）全部為 0。
- 開發代理指標：精修成功但真實位置誤差超出所用餘裕的視角數（decision 029 §4）；v5 不得明顯多於同資料上的 v4。
- 代價 / 改善：Rule budget 2 / 3 / 5、absent@5、不提供看穿的視角數、餘裕中位數；v5 − v4 成對差異。
- 校正品質：ŝ 與真實比例的差、所需的校正視角數。
