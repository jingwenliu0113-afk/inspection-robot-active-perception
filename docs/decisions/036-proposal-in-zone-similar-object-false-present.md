# 036（提案）— zone 內相似物件的誤報：多視角確認能否補足外觀的不足

- **日期**：2026-10-16
- **狀態**：**提案。使用者 2026-10-16 只核准 E0（附錄 A）**；完整方案（E1、H2、E2、正式實驗）未啟動。
- **是否在看過正式結果後才寫**：是。動機來自 R0a（decision 021）、v3 開發（`docs/v3-development.md` §1）與 A（decision 030）已報告的結果。
  所有封存資料（R0a 正式集、detector-v2 test、`detv2-sim`、`v3` / `v4` / `v5` 等）都不使用。
- **使用者指示（2026-10-16）**：下一階段優先處理 zone 內相似物件造成的 detector 誤報；先提出小範圍、假設驅動的方案；Research 與 Engineering 可受控並行，但不直接開始新版本的正式實驗；方案確認後才能啟動。

## 1. 問題與已知事實

在巡檢管線中，zone **內**的相似物件（管件、閥門、立管、路樁、垃圾桶等）只要在任一視角得到信心 ≥ 0.7，就會被判 `present`，也就是錯誤的肯定答案。
zone 過濾（v3 / v4）只能排除 zone **外**的物件。

| 已知 | 數字 | 來源 |
|---|---|---|
| 只調門檻 | 單張誤報 < 1% 需要門檻約 0.98，代價是約 38% 的真消防栓判不出（影像層級） | v3 開發 §1.1 |
| 框形狀過濾 | recall 少 5 個百分點內，誤報只從 9.1% 降到 7.7% | v3 開發 §1.1 |
| 困難負樣本微調 | 確認負樣本誤報 8.4% → 4.7%，未達 ≤ 1%；正樣本完全漏看 4 → 10 / 134 | decision 030 |
| 最危險的混淆 | 開發組 67 張誤報中，管件 / 閥門 / 立管 9 張、柱狀街道設施 17 張 | v3 開發 §1.2 |

外觀這條路已經試過兩次，都沒有達標。但上面的數字全部是**單張影像**，而巡檢管線是**多視角加 depth**。還沒有人量過的是：

> 主動感知看越多視角，相似物件被誤判的機會也越多（目前規則是「任一視角 ≥ 0.7 就 present」）。
> 但如果誤報只在特定角度出現，「要求第二個視角確認」反而能把多視角從風險變成過濾器。

關鍵是一個可以先量的問題：**誤報跟著物件走（每個角度都像），還是跟著視角走（只有某些角度像）？**

## 2. 研究問題與假設

**RQ**：不重新訓練 detector，只利用管線已有的多視角與 depth，能否大幅降低 zone 內相似物件的 false present，而 present 召回的代價可以接受？

| # | 假設 | 量法 | 成立條件（建議，確認時可調） |
|---|---|---|---|
| **H1（機制，先量）** | 相似物件的誤報跟著視角走 | 同一物件、方位相隔 ≥ 45° 的兩個視角：P(視角 j ≥ 0.7 ｜ 視角 i ≥ 0.7) | 相似物件 ≤ 0.5，且真消防栓（清楚可見時）≥ 0.85 |
| H1b（曝光效應，同時量） | 目前規則下，episode 層級的誤報隨視角數上升 | k = 1…5 個隨機不同視角時，「任一 ≥ 0.7」的機率 | 只報告（說明問題的實際大小） |
| **H2（管線，只在 H1 成立時做）** | 「確認式 present」能降低誤報、代價可接受 | 見 §4 | episode 層級誤報相對降低 ≥ 50%；present 召回（Rule budget 3 / 5）下降 ≤ 0.05；安全指標維持 0 |

H1 不成立（誤報跟著物件走）時，多視角幫不上忙，**不做 H2**。剩下的路是外觀或形狀（detector、公制尺寸），屬於另一個方案。

## 4. 候選規則與 baseline（只在 H1 成立後開發）

候選規則（只改判定的 present 分支）：

- `confirm`：present ⇐ 某一視角在 zone 內信心 ≥ τ_hi（例如 0.98），**或**至少 2 個視角在 zone 內信心 ≥ 0.7，且以 depth 定位的位置相距 ≤ r（例如 0.25 m）。
- τ_hi 與 r 只在 E1-dev / E2-dev 上選，凍結後才看 test。

## 7. 對現有巡檢管線的影響

- **只改判定規則的 present 分支**。absent 分支、see-v5、位姿精修、zone 過濾、detector、rule-nbv-v2 都不變，差異可以完整歸因。
- **安全方向**：更嚴格的 present 只會把 present 變成 `inconclusive`，不會產生 false absent。相似物件在 zone 內時，absent 仍會被 `c_block` 擋下。
- **代價**：中等信心（0.7–τ_hi）的真消防栓需要第二個視角。
  - Single View（budget 1）會失去這部分的 present。
  - 小 budget 時 inconclusive 會增加；E2 會量出實際大小。
- rule-nbv-v2 不知道「需要確認」，可能不會去找確認視角。第一輪**刻意不改策略**，避免把兩個變化混在一起；若代價主要來自策略，再另提方案。
- 計算量不變：只用每個視角已經算好的偵測與 depth 定位。
- 凍結的 v1–v5 與所有已報告的結果都不變；若採用，是新版本（v6），用新 namespace。

### A.3 公平比較的條件

- 同一批影像、同樣的前處理（真實照片：camera-equivalent 尺寸；模擬：640×480 乾淨 RGB）、同一個裝置（CPU）、同樣的門檻（present 0.7、absent 0.02）。
- 執行前重算抽樣影像，確認快取可重現（每個快取 20 張，最高信心差 ≤ 1e-3）。
- 已知偏差（報告，不修正）：detector-v2 的設定是在這份 dev 上選的（decision 027 §4，3 個候選），所以 v2 的 dev 數字略偏樂觀。

### A.4 分析

| # | 內容 | 性質 |

### A.5 「是否值得進入 E1」的建議規則（事先寫定；只是研究上的建議，不是產品驗收）

1. 方法可行：E0-1 通過、所有指標都算得出來。
2. **H2 的上限**：τ_hi = 0.98 時，真實照片（確認負樣本）的誤報中 ≥ 0.98 的比例 < 50%（v1 與 v2 分別報告）。
   若 ≥ 50%，即使 H1 完全成立，H2 也達不到「誤報 −50%」，**建議不為 H2 進入 E1**（H1 仍可作為科學問題，由使用者決定）。
3. 消防栓那一側：模擬中 P(j ≥ 0.7 ｜ i ≥ 0.7) ≥ 0.85。若不到，確認式規則在模擬中的召回代價就會很大。
4. r：D1×L1 / D3×L1 下同一物件位置距離的 p95 ≤ 0.25 m。若不到，r 要放大，位置檢查的鑑別力會變弱（報告）。
5. 模擬中 absent 場景沒有誤報（預期）→ 相似物件那一側只能靠 E1 的真實照片；這是 E1 必要性的依據，不是門檻。
