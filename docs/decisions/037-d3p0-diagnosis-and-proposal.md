- **使用者指示（2026-10-16）**：E0 結果接受並封存、E1 暫緩；先研究 Backlog 的 D3×P0；
  分析定位誤差、視角可觀測性與 inconclusive 的關係，區分「真正不可觀測」與「定位不確定造成的失敗」；
  優先用既有開發資料診斷；提出最小可驗證的改善假設、baseline、指標與停止條件；**不得因提高 absent 判定率而增加 false absent**。

## 1. 診斷協定（執行前寫定）

資料：`v3-dev`（120 集，13 個視角；absent 60 集），必要時 `v3-dev-dx`。管線：凍結 v5（v4 ＋ see-v5），`detector-v1`。
條件：**D3×P0**（主要），以及對照 D0×P0、D3×L1、D1×L1、D1×L2（定位器回報 L1，過度自信）。

### 1.1 視角層級

每個視角記錄：精修結果（成功 / 矛盾 → 不提供看穿 / 退化 → 寬餘裕）、精修位姿相對真實位姿的誤差、精修移動量與方向（相對光軸）、
假設離散度、先驗閘門、以及「定位器位姿的擬合成本 ÷ 精修位姿的擬合成本」（可部署的特徵，用來判斷矛盾是否顯著）。
P0 時定位器位姿就是真實位姿，所以精修的任何移動都是精修本身的誤差。

### 1.2 位置層級的分解（absent 集）

對每個 zone 位置，依序在以下處理下判斷是否被清除（`col_min` = 1，see-v5）：

| 代號 | depth | 位姿 | 餘裕 | 說明 |
|---|---|---|---|---|
| T0 | 乾淨 | 真實 | 0 | 結構上可觀測（幾何） |
| T1 | D3 | 真實 | 0 | depth 雜訊下可觀測 |
| T2 | D3 | 真實 | v5 實際使用的餘裕 | 餘裕的代價 |
| T3 | D3 | v5 使用的位姿（不提供看穿的視角清除 0） | v5 | 實際管線 |

差異：T0 未清除 = **真正不可觀測（幾何）**；T0 有、T1 沒有 = **depth 雜訊造成**；T1 有、T2 沒有 = **餘裕造成**；T2 有、T3 沒有 = **定位處理造成**（矛盾 → 不提供看穿、精修誤差）。

分別對「全部 13 個視角」與「Rule 在 budget 5 實際選的視角」計算。

### 1.3 失敗歸因（D3×P0，Rule budget 5 判 inconclusive 的 absent 集）

| 類別 | 條件 |
|---|---|
| 結構 | 全部 13 個視角在 T0 下仍未清除 |
| depth 雜訊 | T0 可清除，T1（13 個視角）不可 |
| 定位 / 餘裕 | T1 或 T2（13 個視角）可清除，T3（13 個視角）不可 |
| 視角選擇 / budget | T3 用全部 13 個視角可清除，但 Rule 選的 5 個視角不行 |

### 1.4 反事實（只用於診斷，使用真實位姿，不可部署）

- C1：矛盾而不提供看穿的視角，改用定位器位姿、餘裕 max(6 cm, 3σ) 時的清除與真實誤差。
  在 D1×L2（回報 L1）同樣計算，用來看「信任定位器」在定位器錯時的危險。

所有反事實與真實位姿只用於歸因，不進入任何可部署的規則。


## 2. 診斷結果（細節見 [docs/d3p0-diagnosis.md](../d3p0-diagnosis.md)，`results/d3p0-diag/summary.json`）

- **沒有真正不可觀測的失敗**：乾淨 depth、真實位姿下，60 個 absent 集用 Rule 選的 5 個視角全部可清除；D3 depth 下 59 / 60。
- **D3×P0 的 14 個失敗全部是「選中的視角被判矛盾而不提供看穿」**：同樣的 5 個視角用真實位姿全部可清除。
- **P0 時矛盾視角 100% 是精修錯**（精修誤差 p50 4.9 cm、p95 14.8 cm）：回報 1 cm 不確定度 → 3 cm 先驗閘門，比 D3 下精修自身的誤差還小。
  D1×L2（定位器過度自信）時則 86% 的矛盾視角中精修比定位器準（272 個定位器誤差超過寬餘裕），矛盾規則在那裡是必要的。
- **可部署的區分特徵**：定位器位姿與精修解的擬合成本比。D3×P0 p50 1.18，定位器真的錯時 p50 32.8。
  c = 1.3 時（路徑固定的離線估計）：D3×P0 救回 12 / 14，D1×L2 只接受 1 個且定位器沒錯，被佔用位置被清除 0。

## 3. 研究方案（提案，待使用者確認）

### 3.1 假設（最小、可驗證）

> **H-P**：當精修與定位器「矛盾」，但定位器位姿解釋 depth 幾乎和精修解一樣好（擬合成本比 ≤ c）時，矛盾不是 depth 所支持的。
> 此時改用**定位器位姿**與既有的失敗擬合餘裕 max(10 cm, 3σ)，而不是讓視角不提供看穿。
> 這能在 D3×P0 下救回大部分 absent 失敗，而不增加 false absent、佔用看穿與超出餘裕。

- 只改「被 v5 判矛盾而不提供看穿」的視角；精修成功、退化（寬餘裕）的視角完全不變。
- 成本比 > c 的矛盾（定位器位姿明顯解釋不了 depth）照舊不提供看穿：保留 v3 為過度自信的定位器加入的保護。
- c = 1.3：開發資料上「定位器錯的視角被接受」為 0 的最大候選值；只在 {1.2, 1.3} 中選，不再調整。
- 餘裕沿用 v3 / v4 已凍結的失敗擬合餘裕，不新增參數。

### 3.2 Baseline 與對照

| 代號 | 內容 | 角色 |
|---|---|---|
| **B0** | 凍結 v5 | 主要 baseline |
| B-floor | v5，但定位器回報的不確定度下限由 1 cm 提高到 3 cm（P0 的閘門變 9 cm） | 「只是下限太小」的替代解釋；預期會更常信任錯誤的精修 |
| Oracle-pose | 真實位姿（T2，診斷用） | 上限，不可部署 |

方法：Rule（主要）、Random、Single、Oracle NBV；budget 1–5。

### 3.3 指標

- **安全（必須維持 0）**：FA、FP、GR、全視角 GR、佔用位置看穿（0.06 m）。
- **安全代理**：被接受的矛盾視角中，真實誤差 > 所用餘裕的數量（必須為 0）；所有使用中視角的超出餘裕數（不得多於 B0）。
- **改善**：D3×P0 的 absent@5 與 Rule budget 2 / 3 / 5（v6 − v5 成對，scene group cluster bootstrap 95% CI）。
- **其他條件**：D0×P0（預期逐項相同：沒有矛盾視角）、D1×L1、D2×L2、D3×L1、D1×L2（回報 L1）、`*-dx`。

### 3.4 停止條件

| 階段 | 停止條件 |
|---|---|
| 開發（`v3-dev` / `v3-dev-dx`，完整管線） | 任何條件出現 FA / FP / GR / 全視角 / 佔用看穿 > 0 → 停止 |
| 開發 | 被接受的矛盾視角中有任何一個真實誤差 > 所用餘裕 → 停止（不放大 c、不加補丁） |
| 開發 | D3×P0 的 absent@5 改善 < +0.10（v5 開發值 0.767）→ 不值得正式測試，停止 |
| 開發 | 任何條件的 Rule 準確率顯著變差（成對 CI 上界 < 0）→ 停止 |
| 開發 | B-floor 在同樣安全條件下也達到同樣改善 → 採用較簡單的 B-floor 作為候選，或兩者都報告由使用者決定 |
| 正式（需使用者另行核准） | 新 namespace、凍結後產生；判準事先寫定；只跑一次 |

### 3.5 對現有管線的影響

- 只影響被判矛盾的視角：多一次擬合成本計算（定位器位姿上的 5 個比例假設），計算量可忽略。
- 不改 see-v5、zone 過濾、decision-v2 門檻、detector、rule-nbv-v2；沒有矛盾視角的條件（D0×P0）結果不變。
- 安全論證：被接受的視角使用與「精修失敗」相同的寬餘裕，只是在 depth 無法分辨時改信定位器；定位器明顯解釋不了 depth 時照舊不提供看穿。
- 若採用，是新版本（v6），v1–v5 的凍結值與結果都不變。

2. c 的候選集合 {1.2, 1.3} 是否接受。

### A.1 管線

| 代號 | 內容 | 可部署 |
|---|---|---|
| **B0** | 凍結 v5（`frozen_v5.GEOMETRY`） | 是 |
| **HP-1.2（主要）** | v5 ＋ H-P，c = 1.2 | 是 |
| HP-1.3（敏感度） | v5 ＋ H-P，c = 1.3 | 是 |
| B-floor | v5，定位器回報不確定度的下限 (1 cm, 0.005 rad) → (3 cm, 0.015 rad) | 是 |
| Oracle-pose | 每個視角用真實位姿、v5 對該視角算出的餘裕，且不判「不提供看穿」 | **否**（上界） |

**H-P 的精確定義**：v5 因「精修與定位器矛盾」（`ref.conflict`，`on_conflict = blind`）而讓視角不提供看穿時，計算

> r = min_s C(定位器位姿, s) ÷ C(精修解)

C 是精修自己的加權對齊成本（同一組點、同一個抽樣、同樣的權重與尺度雅可比），s 取 v5 的 5 個比例假設（0.96–1.04）。
r ≤ c：這個視角改用**定位器位姿**與既有的失敗擬合餘裕 max(10 cm, 3σ) / max(0.06 rad, 3σ_yaw)，看穿規則（see-v5）不變。
r > c 或無法計算：照 v5 不提供看穿。其餘全部不變。r 只用 depth、地圖與定位器位姿。

**B-floor 也提高 yaw 下限**的理由：開發資料 D3×P0 的 454 個不提供看穿視角中，199 個超過 yaw 閘門（40 個只超過 yaw），只提高 xy 不是公平的替代解釋。
L1 / L2 的 σ 都不小於新下限，所以 B-floor 只改變 P0 的條件；搜尋範圍與失敗擬合餘裕也不變（max(15 cm, 4σ)、max(10 cm, 3σ) 的結果相同），
**B-floor 等於只把 P0 的先驗閘門由 3 cm / 0.015 rad 放寬到 9 cm / 0.045 rad**。

### A.2 資料與條件

- `v3-dev`（120 集；absent 60；30 個 scene group）與 `v3-dev-dx`（120 集；absent 60；30 個 scene group）。
- B0、HP-1.2、HP-1.3：兩個 namespace 都跑 D0×P0、D1×L1、D2×L2、D3×L1、D3×P0、D1×L2（定位器回報 L1）。
- B-floor：兩個 namespace 的 D0×P0、D3×P0（其他條件與 B0 相同，見 A.1）。
- Oracle-pose：兩個 namespace 的 D3×P0、D3×L1。
- 四個方法（Single、Random、Rule、Oracle NBV）、budget 1–5、與 v5 開發相同的種子；`detector-v1`；decision-v4 zone 過濾；rule-nbv-v2。
  每個方法都在 H-P 的觀測上重跑完整 harness（Rule 依新的清除狀態重新選視角）。

### A.3 指標

- **安全（可部署管線必須全部為 0）**：FA、FP、GR（四個方法 × budget 1–5）、全視角 GR、佔用位置看穿（0.06 m）。
- **安全代理**：被 H-P 接受的矛盾視角中，真實位置誤差 > 所用餘裕的數量（必須為 0；yaw 一併報告）；使用中視角的超出餘裕總數不多於 B0。
- **改善**：Rule absent@5、Rule budget 2 / 3 / 5 準確率；對 B0 成對比較，scene group cluster bootstrap 95% CI（與 v3–v5 相同的 N_BOOT、種子）；absent@5 只在 absent 集上成對比較。
- **成本**：（a）計算：每個矛盾視角多一次成本計算（5 個比例），實測時間相對於精修；（b）被接受視角的餘裕；（c）B0 對、H-P 錯的集逐一列出。
- **失敗案例**：HP-1.2 在 D3×P0 仍判 inconclusive 的 absent 集逐一歸因；任何 H-P 錯而 B0 對的集。
