- **日期**：2026-10-13
- **狀態**：協定凍結；開發結果與凍結值以本檔附錄記錄；確認批次只跑一次。
- **是否在看過正式結果後才新增 / 修改**：是——起因是 B0 的 C6 未通過（decision 015 附錄 B）。B0 資料（`nav-b0`）本來就是開發資料；
  本檔的效果宣稱只來自**新的確認資料** `nav-b0c`（本檔 commit 之後才產生）。Core 的 v1 / v2、test、holdout、Gate 全部不變。

## 1. 使用者決定（2026-10-13）

採用「位姿精修 + 不確定性餘裕」（AskUserQuestion，建議選項），處理後再依標準進 B1。

## 2. 問題

`decision-v2` 以 depth 判定「看穿」（容忍值 0.03 m）。Core 用 teleport，相機位姿精確；Nav2 下只能用 AMCL 估計位姿，
B0 中位誤差 4.0 cm / 0.023 rad，幾何誤差與容忍值同量級 → 物件存在時仍可能被算成全部看穿（geometric false-absent risk）。

## 3. 設計（不改 `decision-v2` 的任何參數與規則）

### 3.1 位姿精修（`nav-pose-v1`，可部署）

輸入：AMCL 估計（初值）、機載 depth、已知桅桿外參、**先驗設施地圖的向量版本**——牆與柱子的 2D 矩形輪廓
（decision 015 的佔據地圖就是它的柵格化；**不含巡檢目標**，也不含 zone 禁入區）。

1. depth → 3D 點（每 4 個像素取 1、距離 ≤ 6 m）；以估計位姿轉到世界座標，只留高度 0.15–0.85 m 的點（低於所有柱子與牆的高度、高於地面），
   並丟掉落在 zone 中心 0.6 m 內的點（目標可能所在的區域）。
2. 對 (dx, dy, dyaw) 最小化「點到最近牆 / 柱子輪廓距離」的截斷平方誤差（截斷 0.10 m；未知物體與雜點自然成為離群）；
   搜尋範圍 ±0.15 m、±0.08 rad，先粗網格再細化。
3. **可觀測性**：以內點（距離 < 0.03 m）的輪廓法向量建立平移資訊矩陣與旋轉槓桿；最小特徵值低於門檻（例如只看到同一面牆 / 柱面）
   視為**退化**，不採用精修結果。

### 3.2 看穿判定的位姿不確定性餘裕（`nav-margin-v1`）

位置的「看穿比例」改為在一組位姿上取**最小值**：精修位姿 ± δxy（x、y 兩軸）× ± δyaw 的 27 個組合。
只有在所有組合下都被看穿，才算看穿（`decision-v2` 的 `col_min = 1`、`tau_clear = 1` 不變）。

- 精修成功：δ = 開發資料（`nav-b0`）上精修誤差 p95 的 2 倍，下限 0.01 m / 0.005 rad。
- 精修退化或失敗：退回 AMCL 估計，δ = 0.10 m / 0.06 rad（B0 的 AMCL 誤差 p95 再加餘裕）。

δ 與退化門檻只在 `nav-b0` 上決定（附錄 A），之後凍結。

## 4. 驗收（全部成立才進 B1）

開發（`nav-b0`，只用於設計與選參數）之後，在**新的確認資料** `nav-b0c`（新 namespace，6 scene groups × 2 variants，
與 B0 相同流程：每集 12 個候選 + 2 次中途取消）上**只跑一次**：

| # | 標準 |
|---|---|
| R1 | C6 原樣：錯誤肯定答案 = 0；geometric false-absent risk（初始 + 任一停點的組合）= 0 |
| R2 | 所有停點聯集的 geometric false-absent risk = 0（B0 中這一項 2 / 6 不安全） |

任何一項 R1–R3 未成立 → 不進 B1，報告並詢問使用者。成立 → 寫 decision 017（B1 協定）後進 B1。

## 5. GT 使用

精修與餘裕只用可部署輸入（AMCL 初值、機載 depth、向量設施地圖、桅桿外參）。真實位姿只用於評分（精修誤差、geometric risk）。
tests 檢查：精修函式的輸入不含 GT；地圖輪廓不含目標物件。

## 附錄 A（2026-10-13，確認批次之前）：在 `nav-b0` 上的開發與凍結值

開發中修正的一個設計細節：牆用**內側面**（零厚度）作為地圖輪廓。全厚度的牆讓擬合把點滑到外側面
（x、y 各偏 0.10 m = 牆厚，代價反而更低）；機器人永遠在圍牆內，只看得到內側面。

| 凍結值 | 依據（`nav-b0`，180 張） |
|---|---|
| 退化門檻（最小特徵值）10 | 門檻 5–20 結果幾乎相同；取中間值。採用 164 / 180，採用者誤差最大 2.15 cm |
| 精修成功時 δ = 0.015 m / 0.005 rad | 2 × p95（0.74 cm、0.0025 rad），朝向取下限 |
| 退化時 δ = 0.10 m / 0.06 rad | 同 §3.2（AMCL 誤差 p95 加餘裕） |

開發資料上的結果（`results/nav-b0-d016-dev/`，不是驗證）：geometric risk 0 / 168、所有停點聯集 0 / 6、錯誤答案 0、absent → absent 64 / 84（與 B0 相同）。
以上數值凍結於 `activeperception/nav/localize.py`，之後在新的 `nav-b0c` 上只跑一次確認（§4）。

## 附錄 C（2026-10-13，使用者：「再試一次」）：停點視角重定位 + 第二次確認（預先登錄）

1. 等待 1 s，取機載 depth，用 §3.1 的精修（同一組凍結參數）得到精修位姿；精修退化則不做任何修正。
2. 把精修位姿當作 `/initialpose` 發給 AMCL（標準差 0.02 m、0.01 rad），讓定位重新對準。
3. 若精修位姿與目標的差距仍超過 Nav2 到點容忍值（0.07 m 或 0.05 rad），再送一次同一目標讓 Nav2 修正；最多 2 次。
4. 之後才拍攝（拍攝流程不變）。中途取消的停點不做修正（它們本來就是要測試「停錯地方」）。
