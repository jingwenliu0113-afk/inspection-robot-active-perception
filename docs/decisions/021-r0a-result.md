- **狀態**：已判定（R0a 完成）。

- dev（validation，20 張）只用來確認框座標與影像方向（全部 EXIF orientation = 1），沒有調整任何東西。

|---|---|---|---|---|

## 判定（decision 020 §7）

| # | 判準 | 結果 | 判定 |
|---|---|---|---|
| A1 | clear localized recall@0.7 ≥ 0.90 | 97.9% | **通過** |
| A2 | 負樣本 false present ≤ 0.01 | 9.2% | **未通過** |
| A3 | 負樣本 absent blocked ≤ 0.10 | 47.8% | **不可用** |

依事先寫定的解讀：

- **A1 通過**：凍結的 detector 與門檻能辨識網路照片中清楚可見的真實消防栓。
- **A2 未通過**：凍結的 `tau_present` 在真實影像上有錯誤肯定答案的風險，必須先處理才能考慮實機。
- **A3 不可用**：在容易混淆的真實場景中，「判 absent」大多會被擋下，變成 `inconclusive`。這是成本，不影響安全。

## 事後觀察（描述性，不改變判定）

1. **誤報是什麼**：55 張誤報影像目視大致是：
   - 外觀相近的物體：紅色郵筒、水管閥門與立管、牆上水龍頭。
   - 街道上的小型柱狀物：路樁、垃圾桶、三角錐。
   - 玩具、雕像、公仔。
   - 少數影像縮小後難以判斷，可能是標註遺漏的真消防栓。
   - 這些負樣本是「曾被模型懷疑、再由人工否定」的偏難樣本，**9.2% 不代表隨機街景的誤報率**。但巡檢現場（管線、閥門、設備）正好充滿這類物體。
2. **判定規則的結構弱點**：`decision-v2` 取整張影像的最高信心，不管偵測框是否落在 inspection zone 內。
   Gazebo 場景裡沒有干擾物，所以 Core 與 Advanced B 從未暴露這個問題；真實場景中，zone 外的郵筒或閥門也會讓判定變成 present。
3. **幾乎不會完全漏看**：自然遮擋、截斷、小目標的 complete miss 都是 0 / 379。
   完全漏看只出現在人工遮住 75% 時（17.3%）——這正是 v2 必須靠 depth 看穿判定避免 false absent 的情況，也是 R0b 要檢查的。
4. **部分遮擋的轉折點**：遮住一半時仍有 86.8% 達到 0.7；遮住四分之三時降到 23.9%。
   與 Advanced B 的觀察一致：消防栓只露出約四分之一時，信心落在門檻附近（decision 019 / failure analysis §9）。

## 對後續的意義（不在 R0 內執行）

- **R0b 照常進行**：它檢查 depth 與位姿，安全指標（geometric risk、occupied false clearance）與 detector 無關。
- 若要往實機發展，在 A2 處理之前不應採購。候選做法都屬新版本，需要新 decision、新資料，並由使用者決定：
  - (a) 只計入投影落在 inspection zone 內的偵測（用 depth 定位偵測框）；
  - (b) 以真實影像與偏難負樣本微調 detector（SPEC Advanced A）；
  - (c) 兩者並用。
- 本結果只說明網路照片；機器人相機（俯角、距離、動態模糊、曝光）仍未驗證。

## 限制

- 網路照片多半是人拍的正面、近距離構圖，與巡檢機器人的視角分布不同。
- 負樣本只有 600 張偏難樣本；沒有「隨機巡檢場景」的誤報率。
- Open Images 的標註有錯誤的可能（見事後觀察 1）；判定一律依原始標註，不做事後修正。
- 人工遮擋只是灰色長條，不代表真實遮擋物的外觀。
