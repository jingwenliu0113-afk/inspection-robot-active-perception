# 024 — v3 可靠性改善：開發階段計畫與規則

- **日期**：2026-10-14
- **狀態**：開發中。本檔規定 v3 的範圍、開發資料與規則；**正式測試另寫 decision**（規格與判準在那之前凍結，使用未參與開發的新資料）。
- **是否在看過正式結果後才新增 / 修改**：否——v3 沒有任何正式結果。動機來自已報告的 R0a / R0b 結果（decision 021 / 023），那些結果與資料都不再用於 v3 的開發或調參。

## 1. 使用者決定（2026-10-14）

1. 繼續自主開發可靠性改善：R0a 的誤報（zone 過濾、信心校準、困難負樣本）、遮擋下的 absent / inconclusive、R0b 的 depth 品質檢查 / 定位誤差補償 / 不確定性處理、失敗案例與消融實驗。
2. R0 原始結果全部保留，不得修改已封存的資料或門檻。新方法是**獨立版本**，先在開發資料上實作與測試。
3. 若需要新的正式測試：先凍結規格，使用未參與開發的新資料。
4. 不重新訓練或更換 detector（`detector-v1` 不變），不進 RL，不購買硬體；GPU 工作遵守共享 GPU lock。
5. 不為了通過 Gate 修改評測標準。

## 2. v3 的元件（候選，開發中可增減；正式測試前凍結）

| 元件 | 針對 | 內容 |
|---|---|---|
| `see-through-v3` | R0b：缺值像素讓 absent 判不出 | 每個軸點看一小塊鄰域：有效像素夠多、且**全部**有效像素都在預期深度之後，才算看穿；缺值不再自動擋下，也不會被當成看穿 |
| `nav-pose-v3` | R0b：雜訊 depth 讓精修偏移 | 依距離加權（遠處 depth 誤差大）、可選的 depth 比例估計、以兩半點雲各自精修的差異估計不確定性（depth 品質檢查） |
| `nav-margin-v3` | R0b：餘裕假設的誤差太小 | 餘裕依不確定性估計設定；係數只在開發資料上決定 |
| `decision-v3` | R0a：zone 外的相似物件被判 present | 判定只用**位置落在 inspection zone 內**的偵測（以 depth 定位偵測框）；位置無法判斷的偵測不能讓結果變 present，但仍會擋下 absent（保守） |
| `rule-nbv-v3` | v2 的已知限制：分數平手時按編號選 | 平手時改用與已拍視角的角距（novelty）等可部署資訊決定 |

`detector-v1` 的輸出與門檻（`tau_present` 0.7、`tau_absent` 0.02）不變；v3 只改「哪些偵測算數」與幾何判斷。

## 3. 開發資料（新的、與所有正式資料分開）

- **模擬**：
  - 新 namespace `v3-dev`（`gen-nav-v1`，split `r0-dev`）。
  - 先前的開發資料 `r0b-dev`、`nav-b1` 也可以用。
  - 若需要 zone 外的干擾物件，另建開發用的場景變體（只用於開發）。
- **真實照片**：R0a 沒有用到的 Open Images 影像——合格但沒抽中的偏難負樣本（1,473 張），以及人工驗證為正、但沒有框的影像（169 張，只能做影像層級評估）。
  先以固定 seed 各分成兩半：**一半作開發、一半保留給可能的正式測試**，保留的一半在正式規格凍結前不得執行 detector。
- **不得使用**：`core` test、`holdout`、`nav-b2`、R0a 正式集、`r0b`。

## 4. 開發時的評估（與 R0b 相同的指標，不放寬）

- 安全：false absent、geometric risk（策略所選視角）、全視角 geometric risk、佔用位置看穿（物件中心 0.06 m 內）。
- 代價：Rule / Random / Oracle 的準確率、absent 是否可判、inconclusive rate。
- 誤差條件：R0b 的 D0 / D1 / D2 × P0 / L1 / L2（`r0b_noise.py`，不改）。
- 每個元件都做消融（v2 基線、逐一加入、全部），報告在開發結果中，標明是開發資料。

## 5. 不做的事

- 不改 v1 / v2 / decision 016 的凍結值與已報告的結果；v3 的任何結果都另外報告。
- 不在開發階段宣稱任何正式結論；開發數字只用來決定是否值得做正式測試。
